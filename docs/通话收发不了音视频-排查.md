# 通话收不到音视频 · 排查手册

手机端「能看到对方在响铃、能接听，但听不到声音/看不到画面」时，按下面顺序走一遍。

## 0. 先看页面自带诊断

通话界面右上角的 **ⓘ** 按钮，点开会显示实时状态（每 1.5 秒刷新）：

```
连接状态：connected / connected   协商状态：stable   主叫：是
媒体类型：video   掉线重连：否
本地流：audio:live/on video:live/on
远端流：audio:live video:live
远端播放：paused=false muted=false 音量=1
audio 收 128KB  video 收 1024KB
```

对照下表定位：

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 本地流为空 | 权限没给或设备被占用 | 看聊天页顶部红条，按提示重新允许权限 |
| 本地流 `readyState:ended` | 摄像头被其它应用抢占 | 关掉相机/会议类 App 后重拨 |
| 远端流为空且 `连接状态` 不是 connected | 信令没走通 | 刷新页面重拨；看服务端日志有没有「通话开始」 |
| `连接状态 connected` 但 `audio 收 0KB` | 媒体通道没打通，基本是对称 NAT | **必须配 TURN**（见第 2 节） |
| `远端播放 paused=true muted=true` | 浏览器自动播放策略拦下 | 点屏幕上「点击开启声音」 |
| 画面有但没声音 | 手机媒体音量为 0 / 蓝牙输出到耳机 | 调音量、检查蓝牙；点「点击开启声音」 |

## 0.5 手机 → 电脑没有声音（已修复）

**原因**：远端音频原本和画面一起塞在 `<video>` 元素里播放。桌面 Chrome 的自动播放策略会拦下
「带声音的 video」，代码只能退化成本地静音——结果就是画面正常、对方完全听不到。

**修复**：音频与画面彻底拆开——

- `<video id="remote-video">` 永久静音，只负责画面，永远不会触发自动播放拦截；
- 远端音频单独走 **WebAudio**：`AudioContext → GainNode → AnalyserNode → 扬声器`；
- 只需一次用户手势（点一下屏幕任意位置 / 「点击开启声音」）把 AudioContext 从
  `suspended` 恢复成 `running`，之后整通电话（包括重协商、切前后台、ICE 重启）都不会再被拦；
- 不支持的浏览器自动回退到独立的 `<audio>` 元素。

**自检**：通话界面点右上角 **ⓘ**，看这一行：

```
音频引擎：running  远端音量=23/100  音频轨=live/有声音
```

| 显示 | 含义 | 处理 |
| --- | --- | --- |
| `音频引擎：suspended` | 还没解锁 | 点一下屏幕任意位置 |
| `音频引擎：running  远端音量=0/100` | 有连接但对方没出声 | 检查对方麦克风是否被静音 |
| `音频轨=未收到` | 音频轨没协商成功 | 挂断重拨；看是否只拨了视频 |
| 数值在 0~100 之间跳动 | 音频链路正常 | 若仍听不到，检查系统音量/蓝牙输出 |

## 1. 必须满足的前提

1. 站点是 **https**（cloudflared 提供的地址就是 https），http 下 Chrome 直接不给摄像头。
2. 浏览器权限：地址栏锁图标 → 网站设置 → 摄像头、麦克风 → **允许**，然后刷新。
   注意：Chrome 一旦记住「阻止」，不会再弹框，必须手动改。
3. 手机上不要同时开着其它占用摄像头/麦克风的 App（相机、会议、录屏）。
4. 通话中别锁屏：页面已申请 Wake Lock，但如果系统强制息屏，媒体会暂停；切回来会自动 ICE 重启恢复。

## 2. 对称 NAT / 移动网络下必须配 TURN

两端都在 4G/5G 或严格企业网时，公共 STUN 只能发现公网映射，打洞会失败——这时 `连接状态` 会停在 `connected` 之前，或者显示 connected 但收发字节数一直是 0。

解决办法：自建或用现成 TURN，然后在服务端 `data/ice.json` 里配置（**不用改代码、不用重启前端**，刷新页面即可生效）：

```json
{
  "iceServers": [
    { "urls": "stun:stun.cloudflare.com:3478" },
    { "urls": "turn:你的域名或IP:3478", "username": "用户名", "credential": "密码" },
    { "urls": "turn:你的域名或IP:3478?transport=tcp", "username": "用户名", "credential": "密码" }
  ]
}
```

`/api/info` 会把这个配置下发给前端，`window.__ic` 与诊断面板里能看到实际使用的 ICE。

### 最省事的 TURN 搭建方式（VPS 上一行）

```bash
# Debian/Ubuntu
apt-get update && apt-get install -y coturn
# /etc/turnserver.conf：
#   listening-port=3478
#   tls-listening-port=5349
#   fingerprint
#   lt-cred-mech
#   user=intercom:换成你的密码
#   realm=intercom
#   external-ip=服务器公网IP
#   min-port=49160
#   max-port=49200
systemctl enable --now coturn
```

防火墙放行 **3478/udp、3478/tcp、5349/tcp、49160-49200/udp**。

## 3. 临时验证技巧

两台手机都连**同一个 Wi-Fi**（同一网段）再打一次。

- 同一 Wi-Fi 下能通、4G 下不通 → 100% 是对称 NAT，配 TURN 就好。
- 同一 Wi-Fi 下也不通 → 与 NAT 无关，先看第 1 节的权限和诊断面板。

## 4. 服务端日志对照

```
[..] 来电 alice -> bob (video)
[..] 通话开始 alice <-> bob (video)
[..] 通话结束 alice 原因=hangup
```

只要出现「通话开始」，就说明信令已经完全走通，问题一定在媒体通道（NAT/权限/播放策略），不在服务器。
